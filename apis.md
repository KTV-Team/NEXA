# NEXA API implementation guide

The selected APIs serve the shared Android/iOS backend. All paths use the `/api/v1` prefix. New payloads, response models, and operation names below are proposals to define in the shared packages before implementation.

## API inventory

Contract notes show request bodies and the response `data` value. All endpoints require authentication except register, login, and refresh; refresh authenticates through its refresh token.

| Feature  | Operation                   | Method | Endpoint                                        | Function                                                  | Contract notes                                                                                                                                      |
| -------- | --------------------------- | ------ | ----------------------------------------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth`   | `auth.register`             | POST   | `/auth/register`                                | Register an account                                       | Body: `{ email, name, password }`. Return `AuthResponse`; normalize email, hash the password, and enforce account uniqueness.                       |
| `auth`   | `auth.login`                | POST   | `/auth/login`                                   | Sign in                                                   | Body: `{ email, password }`. Return `AuthResponse`; use a generic invalid-credentials error.                                                        |
| `auth`   | `auth.refresh`              | POST   | `/auth/refresh`                                 | Refresh session tokens                                    | Body: `{ refreshToken }`. Return `AuthTokens`; check expiry/revocation and handle token rotation and concurrent refresh safely.                     |
| `auth`   | `auth.logout`               | POST   | `/auth/logout`                                  | Sign out of the current session                           | Revoke the current session/refresh token and unlink its push registration. Return `204`; do not revoke other sessions.                              |
| `user`   | `user.getMe`                | GET    | `/users/me`                                     | Get the current account profile                           | Return the authenticated account's `User`; exclude credentials and token records.                                                                   |
| `user`   | `user.updateMe`             | PATCH  | `/users/me`                                     | Update the current account profile                        | Body: `{ name?, avatarUrl? }`. Return the updated `User`; require at least one allowed field and reject identity/role changes.                      |
| `user`   | `user.search`               | GET    | `/users?q=...`                                  | Search for users                                          | Query: `q` and pagination. Return paginated `UserSummary` records; permitted search fields and visibility need confirmation.                        |
| `friend` | `friend.sendRequest`        | POST   | `/friend-requests`                              | Send a friend request                                     | Body: `{ recipientId }`. Return `FriendRequest`; reject self-requests and handle duplicates, crossed requests, and existing friendships.            |
| `friend` | `friend.listRequests`       | GET    | `/friend-requests?direction=incoming\|outgoing` | List incoming or outgoing friend requests                 | Query: `direction` and pagination. Return only requests involving the current account.                                                              |
| `friend` | `friend.acceptRequest`      | POST   | `/friend-requests/:requestId/accept`            | Accept a friend request                                   | Recipient only; pending request only. Atomically accept and create one friendship. Return `Friendship`.                                             |
| `friend` | `friend.rejectRequest`      | POST   | `/friend-requests/:requestId/reject`            | Reject a friend request                                   | Recipient only; pending request only. Return the updated `FriendRequest`.                                                                           |
| `friend` | `friend.cancelRequest`      | DELETE | `/friend-requests/:requestId`                   | Cancel an outgoing friend request                         | Sender only; pending request only. Record cancellation and return `204`; never remove an accepted friendship here.                                  |
| `friend` | `friend.list`               | GET    | `/friends`                                      | List accepted friends                                     | Query: pagination. Return friendships with permitted friend summaries; also used by the notification recipient picker.                              |
| `friend` | `friend.remove`             | DELETE | `/friends/:friendshipId`                        | Remove a friendship                                       | Either participant may remove the friendship. Return `204`; subsequent sends must fail the friendship check.                                        |
| `noti`   | `noti.create`               | POST   | `/notifications`                                | Create an immediate, scheduled, or recurring notification | Body: content, recipient, and delivery configuration. Return `Notification`; derive the sender from authentication and check recipient permissions. |
| `noti`   | `noti.list`                 | GET    | `/notifications`                                | List notifications created by the current account         | Query: pagination. Return sender-owned notifications with processing/schedule information.                                                          |
| `noti`   | `noti.get`                  | GET    | `/notifications/:id`                            | Get a notification created by the current account         | Sender only. Return `Notification`; recipients use inbox detail instead.                                                                            |
| `noti`   | `noti.update`               | PATCH  | `/notifications/:id`                            | Update notification content or delivery configuration     | Sender only. Return the updated `Notification`; allowed states/fields need confirmation. Detect concurrent updates.                                 |
| `noti`   | `noti.cancel`               | POST   | `/notifications/:id/cancel`                     | Cancel scheduled delivery or stop recurrence              | Sender only. Return the updated `Notification`; coordinate with workers and preserve already-delivered inbox items.                                 |
| `noti`   | `noti.inbox.list`           | GET    | `/inbox`                                        | List received notifications and history                   | Query: pagination and optional `read` boolean. Return recipient-owned `InboxItem` records in a stable order.                                        |
| `noti`   | `noti.inbox.get`            | GET    | `/inbox/:itemId`                                | Get received notification details                         | Inbox owner only. Return `InboxItem` with an authorized target if applicable; handle deleted/inaccessible items opened from push.                   |
| `noti`   | `noti.inbox.getUnreadCount` | GET    | `/inbox/unread-count`                           | Get the unread notification count                         | Return `{ unreadCount }` from the current account's active inbox records.                                                                           |
| `noti`   | `noti.inbox.setReadState`   | PATCH  | `/inbox/:itemId`                                | Mark an inbox item as read or unread                      | Body: `{ read: boolean }`. Return the updated `InboxItem`; set/clear `readAt` and make repeated requests safe.                                      |
| `noti`   | `noti.inbox.markAllRead`    | POST   | `/inbox/read-all`                               | Mark all current inbox items as read                      | Return `{ updatedCount }`; use a server-side cutoff to avoid marking concurrently arriving items read.                                              |
| `noti`   | `noti.inbox.delete`         | DELETE | `/inbox/:itemId`                                | Delete an item from the current account's inbox           | Inbox owner only. Return `204`; preserve the source notification and other recipients' items.                                                       |
